## 🎯 数据特点

### 1. 准确性 ✅
- **史料来源明确**：每条数据标注出处（《宋史》《苏轼年谱》等）
- **时间精确**：具体到年份甚至月份
- **地点可查**：古今地名对照，带GPS坐标

### 2. 旅游化 ✅
- **不只是历史课**：每个事件都设计了"现代体验"
- **可操作性强**：告诉你"在哪朗诵哪首诗""吃什么美食"
- **氛围感拉满**：从"公元1082年"讲到"你可以在月夜泛舟"

### 3. 故事化 ✅
- **不是景点介绍**：而是"某年某月苏轼在这里发生了什么"
- **情感饱满**：从"失意"到"豁达"到"通透"，心路历程完整
- **金句收尾**："把人生低谷活成诗"

## 🚀 使用方法

### 方案A：直接注入Prompt（当前可用）

**生成攻略时，把相关数据作为背景知识注入Prompt：**

```python
# 伪代码示例
def generate_history_route(query):
    # 1. 识别人物（如"苏东坡"）
    person = "苏东坡"
    
    # 2. 加载历史数据
    timeline = load_json("苏东坡/时间线.json")
    poems = load_json("诗词/苏东坡诗词库.json")
    places = load_json("地点/苏东坡路线地点.json")
    
    # 3. 组装Prompt
    prompt = f"""
    你是一个历史旅游攻略生成器。
    
    用户需求：{query}
    
    【历史背景】
    {timeline的核心事件}
    
    【诗词资料】
    {poems的核心诗词}
    
    【地点信息】
    {places的路线地点}
    
    要求：
    1. 严格基于以上史料
    2. 每个地点都讲"为什么来""发生了什么""留下什么诗"
    3. 设计现代体验（在哪朗诵、吃什么、做什么）
    4. 标注史料来源
    """
    
    return AI_generate(prompt)
```

**优点**：
- ✅ 立即可用，无需额外开发
- ✅ 数据可控，准确性高

**缺点**：
- ❌ 数据量大时，Prompt会很长
- ❌ Token消耗多

### 方案B：RAG知识库（未来升级）

**把史书原文切成chunks，存入向量数据库，检索后注入Prompt**

**技术栈：**
- ChromaDB / Pinecone（向量数据库）
- 收集史料：《苏轼年谱》《东坡志林》等
- 切分chunks，生成embeddings

**生成流程：**
```
用户输入"苏东坡被贬路线"
    ↓
1. 检索向量数据库（查询"苏轼 黄州 赤壁"等关键词）
2. 拉取相关史料chunks
3. 结合结构化数据（时间线/诗词/地点）
4. 注入Prompt
5. AI生成攻略
```

**优点**：
- ✅ 可持续扩展（添加更多史料）
- ✅ 更深度（能引用史书原文）
- ✅ 可溯源（每段内容标注来自哪本书哪一页）

**缺点**：
- ❌ 需要开发RAG系统
- ❌ 需要收集、处理大量史料文本

## 💡 数据设计原则

### 1. 准确性 > 趣味性
❌ 错：为了好看，编造细节
✅ 对：没有史料支撑的，不写或标注"据传"

### 2. 旅游化 > 学术化
❌ 错："公元1082年7月16日，苏轼作《念奴娇》一首。"（教科书式）
✅ 对："1082年某个月圆之夜，苏东坡和朋友泛舟赤壁，江水汤汤，明月皎皎...你可以在赤壁矶租船，学他'泛舟赤壁'。"（旅游化）

### 3. 故事化 > 列表化
❌ 错：黄州景点：1.赤壁公园 2.遗爱湖 3.东坡肉
✅ 对：1080年，苏东坡被贬黄州，生活困顿...于是开荒种田，自号"东坡居士"...某个月夜，他泛舟赤壁...

### 4. 可溯源
✅ 每条数据都标注史料来源
✅ 有争议的内容，注明"据传"或"一说"

## 🎯 成功标准

**好的历史数据应该做到：**

1. **用户信任** - "这些是真的吗？" → "有史料来源，可信"
2. **深度体验** - "不只是看景点" → "感受苏轼的心路历程"
3. **可操作性** - "我该怎么玩？" → "月夜泛舟赤壁，朗诵《念奴娇》"
4. **情感共鸣** - "我为什么要走这条路？" → "体验'从挫折到豁达'的人生哲学"
