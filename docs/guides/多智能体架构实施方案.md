## 一、核心架构设计

### 1.1 全局状态对象 (TripState)

**位置:** `backend/core/trip_state.py`

**设计思路:**
- ✅ 所有 Agent 共享同一个结构化状态对象
- ✅ 避免"鸡同鸭讲",每个 Agent 只操作自己负责的字段
- ✅ 类似流水线上的产品,每个工位只负责自己的部分

**核心结构:**
```python
class TripState:
    # 用户输入
    original_query: str
    user_id: str
    
    # Profile Agent 填充
    preferences: UserPreferences  # 偏好
    requirements: TripRequirements  # 需求
    
    # Wild-Routing Agent 填充
    itinerary: List[DailyItinerary]  # 行程
    hotels: List[HotelRecommendation]  # 酒店
    restaurants: List[RestaurantRecommendation]  # 餐厅
    
    # Pricing Agent 填充
    pricing_insights: List[PricingInsight]  # 比价建议
    
    # Content Agent 填充
    markdown_content: str  # Markdown 攻略
    xiaohongshu_content: str  # 小红书内容
```

**优势:**
- 状态可序列化为 JSON,方便存储和传递
- 每个 Agent 通过 `get_context_for_agent()` 只看到自己需要的信息
- 支持断点续传(如果某个 Agent 失败,可以从上次状态恢复)

---

### 1.2 Agent 编排器 (Orchestrator)

**位置:** `backend/core/agent_orchestrator.py`

**设计思路:**
- ✅ 基于 DAG (有向无环图) 的执行流程
- ✅ 自动根据依赖关系确定执行顺序
- ✅ 支持并行执行无依赖的 Agent (未来扩展)

**执行流程:**
```
Profile Agent (提取偏好)
    ↓
Wild-Routing Agent (生成行程)
    ↓
Pricing Agent (比价建议)
    ↓
Content Agent (生成分享内容)
```

**代码示例:**
```python
orchestrator = create_trip_orchestrator()

# 执行完整链路
final_state = await orchestrator.execute(
    initial_state=TripState(
        original_query="海口3天游,带两个孩子",
        session_id="xxx"
    ),
    progress_callback=emit_progress
)
```

## 二、四个核心 Agent 的实现

### 2.1 Profile Agent (用户偏好提取)

**位置:** `backend/services/user_profile.py`

**职责:**
- 从用户查询中提取结构化偏好
- 增强 Prompt,让后续 Agent 理解用户约束

**提取能力:**
- ✅ 亲子出行 (孩子年龄)
- ✅ 预算等级 (low/mid/high)
- ✅ 旅行风格 (文化/自然/美食/休闲)
- ✅ 装备设备 (相机/无人机)
- ✅ 行动能力 (正常/受限)
- ✅ 饮食限制 (素食/清真)

**示例输入输出:**

```
  "kids_ages": [7, 4],
  "budget_level": "mid",
  "travel_style": [],
  "equipment": [],
  "mobility": "normal",
  "dietary": []
}
```

### 2.2 Wild-Routing Agent (野路子规划)

**位置:** `backend/core/agent_orchestrator.py` (wild_routing_agent_handler)

**职责:**
- 调用 AI 生成个性化行程
- 解析 Markdown 内容,提取结构化数据
- 应用"反套路"规则

**核心逻辑:**
```python
# 1. 根据偏好增强 Prompt
enhanced_prompt = enhance_prompt_with_preferences(
    base_prompt, 
    state.preferences
)

# 2. 调用 AI 生成
content = ai_engine.generate(enhanced_prompt, query, mode='full')

# 3. 解析结构化数据
state.itinerary = parse_itinerary(content)
state.hotels = parse_hotels(content)
state.restaurants = parse_restaurants(content)
```

**反套路规则 (Anti-Routine):**
- ❌ 不推荐抖音播放量 > 100万的网红景点
- ❌ 不推荐需要排队 > 1小时的餐厅
- ✅ 优先推荐小红书 < 500篇笔记的宝藏地
- ✅ 优先推荐本地人周末去的地方

---

### 2.3 Pricing Agent (智能比价)

**位置:** `backend/core/agent_orchestrator.py` (pricing_agent_handler)

**职责:**
- 调用 `pricing-system` 监控酒店价格
- 生成"何时订最划算"的建议
- 对比美团/飞猪/携程的价格

**核心功能:**
```python
for hotel in state.hotels:
    # 查询价格趋势
    insight = pricing_monitor.check_price(
        hotel_name=hotel.name,
        destination=state.requirements.destination,
        check_in_date=state.requirements.start_date
    )
    
    if insight:
        # 价格在低位,建议立即预订
        if insight.trend == 'rising':
            insight.suggestion = "价格正在上涨,建议尽快预订"
        elif insight.trend == 'falling':
            insight.suggestion = "价格下降中,可再观察1-2天"
        
        state.pricing_insights.append(insight)
```

**输出示例:**
```markdown
💰 比价建议

海口朗廷酒店:
- 携程: ¥680/晚 ⬇️ (比昨天降¥50)
- 飞猪: ¥720/晚
- 美团: ¥690/晚

💡 建议: 现在订最划算!携程处于近7天最低价
```

## 三、与现有代码的集成

### 3.1 修改现有的生成流程

**当前:** `backend/api/generate.py` 的 `run_generation_task()`

**调整后:**
```python
def run_generation_task(task_id, query, mode, options, user_id):
    try:
        # 🔥 创建初始状态
        initial_state = TripState(
            original_query=query,
            user_id=user_id,
            session_id=task_id,
            requirements=TripRequirements(
                destination=extract_city_name(query),
                days=extract_days(query),
                budget=extract_budget(query),
                travelers=options.get('travelers', 1)
            )
        )
        
        # 🔥 创建编排器
        orchestrator = create_trip_orchestrator()
        
        # 🔥 执行 Agent 链路
        final_state = await orchestrator.execute(
            initial_state,
            progress_callback=lambda p, m: emit_progress(socketio, task_id, 'agent', m, p)
        )
        
        # 🔥 保存结果
        active_tasks[task_id]['result'] = {
            'content': final_state.markdown_content,
            'recommendations': {
                'hotels': [h.dict() for h in final_state.hotels],
                'restaurants': [r.dict() for r in final_state.restaurants],
            },
            'pricing_insights': [p.dict() for p in final_state.pricing_insights],
            'xiaohongshu_content': final_state.xiaohongshu_content
        }
        
    except Exception as e:
        logger.error(f"生成失败: {e}")
        raise
```

## 五、与 Gemini 建议的对比

### ✅ 采纳的建议:
1. 全局状态对象 (Global State Object)
2. Agent 编排和依赖管理
3. 避免"鸡同鸭讲"的上下文隔离
4. 结构化的状态传递

### 🔧 调整的部分:
1. **暂不使用 LangGraph** - 自己实现更轻量的编排器,避免引入复杂依赖
2. **分阶段实施** - 不是一次性做完所有 Agent,先做 MVP
3. **Profile Agent 轻量化** - 先用关键词匹配,不用复杂的 NLP
4. **Web3 暂缓** - 先用传统的积分体系

```python
state_json = trip_state.to_json()
```
